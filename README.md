# ESTADEL · Мониторинг интеграций

Адаптивный журнал тестовых вебхуков со статистикой, фильтром по статусу, сортировкой по времени, панелью деталей и формой добавления события. Интерфейс написан на Vue 3 и TypeScript, сборка работает на Vite, API использует встроенный HTTP-модуль Node.js.

## Запуск

Нужен Node.js 22.12 или новее. Выполните из каталога проекта.

```sh
npm ci
npm start
```

`npm start` собирает интерфейс и запускает сервер. Откройте [http://127.0.0.1:3000](http://127.0.0.1:3000) и нажмите «Добавить тестовое событие», чтобы проверить форму.

## Демонстрация API

`GET /api/events` возвращает журнал. Для `POST /api/events` обязательны `source`, `type`, `status` (`success` или `error`) и `message`. Сервер присваивает последовательный `id` и время в UTC.

```sh
# 201 Created
curl -i http://127.0.0.1:3000/api/events \
  -H 'Content-Type: application/json' \
  -d '{"source":"Тестовый вебхук","type":"lead.created","status":"success","message":"Тестовая заявка принята"}'

# 400 Bad Request при отсутствии message
curl -i http://127.0.0.1:3000/api/events \
  -H 'Content-Type: application/json' \
  -d '{"source":"Тестовый вебхук","type":"lead.created","status":"success"}'
```

## Проверки

```sh
npx playwright install chromium
npm run typecheck
npm test
```

`npm test` запускает тесты API и браузерные тесты формы в Playwright.

## Ограничения

Сервер слушает `127.0.0.1` и загружает 12 вымышленных событий из `content/seed-events.json`. Новые записи хранятся в памяти до перезапуска. Открытая вкладка запрашивает весь журнал каждые пять секунд.

## Подход к реализации

Счётчики и список строятся из одного ответа API, поэтому обновляются согласованно. Счётчики охватывают весь журнал при любом фильтре, чтобы оператор видел общий объём ошибок.
