# ESTADEL · Мониторинг интеграций

Локальный прототип для разбора тестовых вебхуков. Журнал показывает время, источник, тип, статус и описание события. Счётчики охватывают весь журнал, фильтр переключает видимые строки, а детали показывают полное описание и идентификатор события. Нажмите «Время» в заголовке таблицы, чтобы переключить порядок событий. На узком экране сортировка доступна над карточками журнала.

## Запуск

Нужен Node.js 22.12 или новее. Выполните команды из каталога репозитория.

```sh
npm ci
npm start
```

`npm start` собирает фронтенд и запускает Node.js-сервер. Откройте [http://127.0.0.1:3000](http://127.0.0.1:3000). Порт можно сменить через `PORT=3001 npm start`.

Интерфейс написан на Vue 3 и TypeScript, сборка работает на Vite. В режиме разработки запустите API командой `node server/index.js`, затем `npm run dev` в другом терминале. Vite проксирует `/api` на локальный сервер.

Сервер использует встроенный HTTP-модуль Node.js. `server/index.js` запускает процесс, `server/app.js` собирает сервер и связывает маршруты, а `server/events.js` ведёт журнал и проверяет данные событий. Тесты используют `createAppServer`, чтобы запускать отдельные экземпляры с чистыми данными на свободных портах.

## Добавление события из журнала

Нажмите «Добавить тестовое событие», укажите источник, тип, статус и описание. Для статуса «Ошибка» опишите причину. После сохранения запись появится в журнале с учётом выбранной сортировки. Если выбранный фильтр исключает новый статус, журнал переключится на «Все».

Чтобы увидеть отправку в браузере, откройте вкладку Network в инструментах разработчика перед сохранением и выберите `POST /api/events`. В запросе видны отправленные поля, в ответе `201 Created` — созданное событие с ID и временем.

## Демонстрация API

`GET /api/events` возвращает `200 OK` и массив событий в порядке поступления, начиная с новых. Каждое событие содержит `id`, `source`, `type`, `status`, `created_at` и `message`.

```sh
curl -i http://127.0.0.1:3000/api/events
```

`POST /api/events` принимает JSON с четырьмя обязательными строковыми полями. `source` и `type` содержат до 80 символов, `message` до 500, а `status` принимает значение `success` или `error`. Строки очищаются от крайних пробелов. Для ошибки укажите причину в `message`. Сервер присваивает следующий `id` после стартовых событий (`evt-1013`, `evt-1014` и далее), задаёт `created_at` в UTC и игнорирует дополнительные поля.

Успешный запрос возвращает `201 Created` и сохранённое событие. Откройте фильтр «Все» или «Успешно», чтобы увидеть событие после автообновления журнала. Кнопка «Обновить» загружает его сразу.

```sh
curl -i http://127.0.0.1:3000/api/events \
  -H 'Content-Type: application/json' \
  -d '{"source":"Тестовый вебхук","type":"lead.created","status":"success","message":"Тестовая заявка принята"}'
```

Без `message` сервер возвращает `400 Bad Request` с пояснением в `error.fields.message`. Число событий остаётся прежним.

```sh
curl -i http://127.0.0.1:3000/api/events \
  -H 'Content-Type: application/json' \
  -d '{"source":"Тестовый вебхук","type":"lead.created","status":"success"}'
```

Сервер также возвращает `400` при некорректном JSON, `413` для тела больше 16 КиБ и `415` для запроса без `Content-Type: application/json`.

## Проверки

```sh
npx playwright install chromium
npm run typecheck
npm test
```

`npm test` запускает тесты HTTP API и браузерные тесты формы. API-тесты проверяют начальный журнал, сохранение события, последовательные ID и отклонение некорректных запросов. Браузерные тесты проверяют отправку формы в API, появление записи, обработку ошибок и защиту от повторной отправки. Наборы можно запустить отдельно через `npm run test:api` и `npm run test:e2e`.

## Допущения и ограничения

- При запуске сервер загружает вымышленные события из `content/seed-events.json`. Новые записи живут в памяти до перезапуска процесса.
- Сервер доступен локально через `127.0.0.1`. Прототип рассчитан на работу с тестовыми данными.
- Журнал показывает время в МСК. Открытая вкладка опрашивает API каждые пять секунд и позволяет обновить список вручную.
- Автообновление загружает журнал целиком. Размер набора данных рассчитан на демонстрацию.

## Подход к реализации

Один снимок API питает и счётчики, и журнал, поэтому они согласованы после каждого обновления. Глобальная статистика сохраняет общий контекст, пока оператор разбирает ошибки в отфильтрованном списке.

## Роли агентов Codex

- **Оркестратор** согласовывал контракт API и границы задач, объединял изменения и проверял работу приложения целиком.
- **Фронтенд-агент (`frontend`)** реализовал журнал и форму добавления событий, перенёс интерфейс на Vue 3 и TypeScript и проверил адаптивность и управление с клавиатуры.
- **Серверный агент (`backend`)** реализовал API и валидацию, разделил серверный код, вынес стартовые события в `content/seed-events.json` и подготовил API-тесты и браузерные тесты формы в Playwright.
- **Дизайнер (`designer`)** оценил уже собранную Vue-версию на широком и узком экранах. Он проверил расположение элементов, основные сценарии и сообщения формы, а также предложил компактную раскладку кнопок на телефоне.
- **Независимый ревьюер (`review`)** сверял реализацию с ТЗ и последующими требованиями, воспроизводил найденные дефекты и перепроверял итоговую версию после переноса на Vue.
